## What was built today

### 1. Profiles & PermSets — Multi-Object Export
- Checkbox selection in the middle column to choose specific objects before exporting
- "Select All Visible" / "Clear Selected" header controls
- Export button shows count: "📥 Export N Objects" — disabled when nothing selected
- One Excel workbook per principal, one sheet per object — no more single-file-per-object
- **Exported Workbooks** history panel in sidebar showing each export with `~/Downloads` friendly path
- **Help `?` modal** with step-by-step instructions

### 2. FLS Explorer — Single "Open Workbook" button
- Replaced per-file buttons with a single `📂 Open Workbook` button showing `~/Downloads`

### 3. In-Process FLS Cache
- `_principal_cache` dict in `backend/main.py` with 5-minute TTL
- Query 1 (bulk FLS fetch) is cached per `(alias, type, name)` — subsequent exports for the same principal hit cache instantly
- Cache is invalidated on org switch

### 4. Apex Runner — Dev Console redesign
- Per-category debug levels: Db / Workflow / Validation / Callouts / Apex Code / Apex Profiling
- Dev Console-style log rendering: USER_DEBUG highlighted green, milestones blue, noise gray
- Filter buttons: All / USER_DEBUG / Limits / Errors
- Collapsible Debug Log panel at the bottom
- Fixed SF CLI `rc=2` update warning breaking execution
- Fixed `--log-level` flag (doesn't exist in modern SF CLI — removed)

### 5. Global API Limits Footer
- Footer bar on all tabs: "Org API calls 1,125 / 441,450 (0%)"
- Color: green < 50%, yellow 50–80%, red > 80%
- ↻ refresh button, `?` opens a modal explaining what counts as an API call
- `onApiCall` callback passed to all tabs — triggers refresh after any operation
- Backend: `GET /api/orgs/{alias}/limits` fetches from Salesforce REST `/services/data/vXX/limits`
- Fixed SF CLI token redaction: uses `sf org auth show-access-token` (not `sf org display`)

### 6. Claude AI Assistant — Split Panel in Apex Runner
- `✨ AI` toggle button splits the layout 50/50 (editor left, Claude panel right)
- Quick chips: ✨ Explain / 🔧 Fix / 🧪 Write Test / ⚡ Optimize
- Editor code + last 50 lines of execution log sent as context automatically
- Code blocks in responses have **→ Replace** and **+ Append** buttons on hover
- Streaming SSE via `apiStream()` from `client.js` (same pattern as export progress)
- Conversation persists for the session; 🗑 Clear to reset
- Friendly error message when API key is missing, pointing to Settings

### 7. Settings Modal — Global Header
- **⚙ Settings** button in the top bar (all tabs)
- Fields: API Key (password), Gateway URL (leave blank for api.anthropic.com), Model (picklist)
- API key saved to `~/.anthropic_key`; model + base_url saved to `~/.vendavis_config.json`
- **Model picklist** with 10 options: Sonnet 4.6, Sonnet 5, Opus 4.6/4.7/4.8 — each in standard and 1M context variants
- **Legacy config fallback**: reads `~/.sf_tools_config.json` (SOQL Explorer config) for both key and base_url — so users with the old tool already configured don't need to re-enter anything
- Settings modal shows "✓ using key from SOQL Explorer config" when falling back to legacy
- Backend forces `ClaudeClient` rebuild (`_claude._client = None`) after settings save — no restart needed

## Known issues / gotchas

- **SF CLI rc=2**: SF CLI returns exit code 2 for "update available" warnings even on success. Fixed by parsing stdout as JSON first and ignoring rc when parsing succeeds.
- **Token redaction**: `sf org display` redacts access tokens. Must use `sf org auth show-access-token --target-org <alias>` to get the real token for REST API calls.
- **Tauri SSE streaming**: Tauri's `api_post` IPC command buffers the full response before returning — it cannot stream. All SSE endpoints (export progress, Claude chat) use `apiStream()` from `client.js` which bypasses Tauri IPC and fetches directly via `window.__SF_BACKEND_PORT__`.
- **Model IDs**: The 1M context window model IDs (e.g., `claude-opus-4-7-thinking`) are best-guess — verify against the gateway's supported model list if those specific IDs fail.
