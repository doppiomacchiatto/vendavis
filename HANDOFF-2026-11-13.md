## ⚠️ First thing: fix the Apex Runner "💾 Save" button

**Symptom (reported by the developer, 2026-11-13):** in Apex Runner → AI panel, hovering a code block shows **💾 Save** next to → Replace / + Append. Clicking it does **nothing**: no dialog, no banner. (Replace/Append work.)

**Code:** `frontend/src/pages/ApexRunner.jsx` (`AiPanel`: `saveOne`, `saveAll`, `writeEntries`, the overwrite/result banners) and `frontend/src/apexExport.js` (pure helpers; unit-checked, 29 assertions passed). Commit `a2c05db`.

**Most likely cause (strong evidence, not yet confirmed in the running app):**
`saveOne` calls `openSaveDialog()` from `frontend/src/api/client.js`:
```js
export async function openSaveDialog(opts = {}) {
  if (window.__TAURI__) { const { save } = await import("@tauri-apps/plugin-dialog"); return save(opts); }
  return null;            // <- silent
}
```
`saveOne` then does `if (!path) return;`, so a `null` is indistinguishable from "user cancelled". In Tauri v2 `window.__TAURI__` only exists when `app.withGlobalTauri` is `true`. `src-tauri/tauri.conf.json` `app` block has only `windows` and `security`, and `main.rs` never sets it (it only sets `window.__SF_BACKEND_PORT__`). `window.__TAURI_INTERNALS__` is always present in Tauri v2 and is the reliable check.
The **Health export works** because `OrgHealth.jsx` imports `save` from `@tauri-apps/plugin-dialog` directly (no global check).
`openDirDialog()` (used by **Save all**) has the same guard and falls back to `window.prompt`, which returns null in WebView2 → Save all would also silently do nothing.

**How to confirm (5 minutes):** in `saveOne`, add `debugLog(...)` lines (import from `../debugLog`): `typeof window.__TAURI__`, `typeof window.__TAURI_INTERNALS__`, and the value `openSaveDialog` returns. Rebuild, click Save, open the 🐞 Debug modal (devtools are off in release, the debug log works).

**Suggested fix:**
1. Import the dialog functions directly: `import { save, open } from "@tauri-apps/plugin-dialog"` in `ApexRunner.jsx` (same pattern as `OrgHealth.jsx`), or change the helpers in `client.js` to check `window.__TAURI_INTERNALS__` (or just import the plugin unconditionally inside try/catch).
2. **Never fail silently:** distinguish "cancelled" from "dialog unavailable/errored" and show the red banner for the latter.
3. Do **not** flip `withGlobalTauri` to true unless there is a reason (larger attack surface).

**Audit the same pattern elsewhere** (all rely on `window.__TAURI__`, which is probably undefined in the packaged app):
- `client.js:13` (`getInvoke`; `api()` then silently uses plain `fetch` to `localhost:<port>`, which the CSP allows — that is why the app works at all), `client.js:158/170` (the dialog helpers)
- `App.jsx:101` (About shows the Tauri version — probably never runs, so it shows the default)
- `FlsExplorer.jsx:234-235,271` and `ProfilesExplorer.jsx:142-143,219` (`openDirDialog` for workbook export; **check that export folder selection works in the packaged app**)

**Done criteria:** hover a block → 💾 Save → native Save dialog opens with the class name → `X.cls` and `X.cls-meta.xml` exist; Save all on a 2-class answer (test class + `TestDataFactory`) writes 4 files; running Save all again on the same folder shows the amber overwrite bar; Cancel in the dialog does nothing (no error).

## Things that will bite you (new this session)

- **The desktop client only sends GET and POST** through Tauri (`api_get` / `api_post`). A `DELETE`/`PUT` becomes a POST to the same path. Add a POST alias route for anything destructive (see `/api/ai/skills/remove`).
- **`api()` logs every failure** to the debug log. For polling use `waitForBackend()` (quiet).
- **`window.__TAURI__` is probably undefined** in the packaged app (see the Save bug). Import plugins directly instead.
- **`_sf()` returns CLI error JSON instead of raising.** Always check `status` (this hid the Security Settings and validation-rule failures). Commands that need a project need `cwd=` (a temp `sfdx-project.json`), and the retrieve/deploy target dir must not overlap the package directory.
- **Never deploy a stub to toggle a validation rule** — it overwrites the formula and message. Use the Tooling API `Metadata` read-modify-write in `toggle_validation_rule`.
- **Skill detection only reads user messages.** Added skills are injected only when a built-in skill is detected.
- **Skill text is upstream (`forcedotcom/sf-skills`)** — bundled copies match upstream byte for byte, including its mistakes. GitHub raw path is `.../main/skills/<slug>/`.
- **Python 3.9 support** is claimed in the README: avoid 3.10+ APIs (`tempfile ignore_cleanup_errors`, `zip(strict=)`, `X | None` at runtime without `from __future__ import annotations`).
- **PowerShell 5 mojibake:** set `[Console]::OutputEncoding = [Text.Encoding]::UTF8` before `git show`/`Get-Content` of files with emoji or em dashes, and write files as UTF-8 without BOM. Working-tree files are CRLF.
- **Red `NativeCommandError` after `git push`/`git fetch`/`cargo` in PowerShell is harmless** (progress goes to stderr).
- Secrets: `%APPDATA%\Avio\api_key` is a plain-text key. Never print or log it.
